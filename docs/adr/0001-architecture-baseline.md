# ADR-0001: Базовая архитектура и локальное хранение данных

Дата создания: 2026-02-24
Автор: Команда проекта
Статус: Принято

## Контекст
Проект — мобильный помощник по ментальному здоровью с дневником настроения, чат-ботом и рекомендациями. Требования: офлайн-доступ, приватность данных, быстрая итерация и минимальные инфраструктурные затраты. Команда небольшая, поэтому нужна простая и прозрачная архитектура, которую легко поддерживать.

## Принятое решение
Выбрана локальная, офлайн-ориентированная архитектура на Flutter с четким разделением слоев и шифрованным хранением чувствительных данных.

Решения:
- Клиент: Flutter (Material 3), основная целевая платформа — Android. UI разделен по фичам.
- Состояние: Provider, инициализация провайдеров в `main.dart`, реактивные обновления UI.
- Навигация: `go_router` с централизованными маршрутами.
- Данные: зашифрованная SQLite через `sqflite_sqlcipher` для дневника настроения и истории чата; ключ шифрования хранится в `FlutterSecureStorage`.
- Репозитории: интерфейсы `MoodRepository` и `ChatRepository` с SQLite-реализациями и in-memory версиями для тестов.
- Настройки: JSON-файл через `StorageService` (нечувствительные данные).
- ML: on-device TFLite модель для предсказания и рекомендаций, с безопасным fallback при отсутствии модели.
- Чат-бот: локальные правила по ключевым словам, без внешних API.

## Альтернативы
- Riverpod или BLoC вместо Provider для более строгой архитектуры, но с повышением сложности для текущего размера команды.
- Серверная БД или Firebase для синхронизации и аналитики, но это требует инфраструктуры, увеличивает риски приватности и усложняет соответствие требованиям.
- Hive как основное хранилище вместо SQLite, но сложнее обеспечить транзакционность и структурированные запросы.
- Облачные LLM/ML вместо TFLite, но это приводит к зависимости от сети, затратам и рискам утечки чувствительных данных.
- Ручная навигация на Navigator 2.0 без `go_router`, но сложнее поддерживать маршруты.

## Последствия
Плюсы:
- Полная офлайн-работа, высокая приватность, минимальные операционные затраты.
- Простая архитектура, понятная для команды и удобная для дальнейшего развития.
- Чувствительные данные защищены шифрованием на устройстве.

Минусы:
- Нет синхронизации между устройствами без будущей серверной части.
- ML и чат-бот ограничены ресурсами устройства и качеством локальных моделей.
- Нужно поддерживать миграции SQLite и ключи шифрования.
